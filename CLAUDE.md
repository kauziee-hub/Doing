# Hirora — project conventions & status

Windows 11 x64 interview copilot that runs **entirely on the PC** since 0.3.0 (formerly **VeyraCue**, renamed in 0.2.0). Original specs (kept verbatim, still say VeyraCue): `docs/CLAUDE_CODE_MASTER_PROMPT.md`, `docs/VEYRACUE_IMPLEMENTATION_PLAN.md`. The repo folder was `VEYRACUE` until 2026-11-26 and is now `Hirora`; after a folder move run `CI=true pnpm install --frozen-lockfile --prefer-offline --config.confirmModulesPurge=false` (pnpm's links hold absolute paths, so builds fail with "Cannot find module …\vite.js").

## Layout
- `apps/desktop` — Electron 45 (main/preload in `electron/`, React renderer in `src/`), electron-vite 6, electron-builder 26 (`electron-builder.yml`, appId `app.hirora.desktop`).
- `apps/hosting` — Vercel project `hirora` (team `omniwebora`), live at https://hirora-one.vercel.app: serves only the built website (`public/` = copy of `apps/website/dist`, gitignored). No server code since 0.3.0 (the Hirora Cloud relay was deleted). Installers are GitHub release assets of `kauziee-hub/hirora` (tag `v<version>`) since 0.3.6; 0.3.5 and older were on Vercel Blob (store `hirora-releases`), which was suspended on 2026-11-26 (billing state Inactive, 980 MB, likely the Hobby plan's Blob limits) and serves 403s.
- `apps/website` — multi-page static site (Vite MPA): `index`, `features`, `download`, `guide`, `privacy`, `faq`, `changelog` (.html), shared `partials/header.html` + `footer.html` injected by the `hirora-partials` plugin in `vite.config.ts`. Positioned as a **free local meeting assistant**; interview practice is one use case lower on Home with the responsible-use note. `scripts/prepare-release.mjs` copies the installer info + screenshots (`tools/site-shots.mjs`) and writes `src/release.json` (SHA-256). Hero: the Higgsfield portrait on concentric rings + soft glow (no floating chips — the owner disliked them). `tools/make-og.py` makes the social card.
- `native/windows-audio` — Rust WASAPI helper (`hirora-audio.exe`): mic + loopback + per-process loopback, 16 kHz mono PCM16 20 ms frames, framed stdout protocol (`src/protocol.rs`, mirrored by `electron/main/audioHelper.ts`), JSON-line stdin commands.
- `apps/desktop/electron/main/engine/` — **the only engine** (ADR 0012): `catalog.ts` (pinned URLs/sizes/SHA-256 per tier), `download.ts` (resumable verified downloads, `tar.exe` unzip), `servers.ts` (whisper-server on 127.0.0.1:8178, `ollama serve` on 127.0.0.1:11435 with 2 parallel slots), `index.ts` (`EngineManager`: nvidia-smi tier, setup, start/stop, reuse of a user-installed Ollama and its models).
- `packages/contracts` (Zod schemas, IPC allowlist incl. `engine:*`, settings schema 2, secret detector) · `providers` (Ollama answer client + whisper.cpp transcriber only) · `knowledge` · `orchestration` · `settings` · `ui`.
- `electron/main/migrate.ts` — copies `%APPDATA%\VeyraCue` → `%APPDATA%\Hirora` before Chromium reads `Local State` (keeps DPAPI keys decryptable); retries every launch until a marker `.migrated-from-veyracue` is written; never overwrites a Hirora profile that has its own keys (ADR 0009).
- `tests/e2e` (Playwright-for-Electron: `app.e2e.ts`, `capture.e2e.ts`, `hardware.e2e.ts`; all run with an empty engine folder; `HIRORA_E2E_EXE=<exe>` targets a packaged build), `tests/fixtures`.

## Rules
- Public repo: https://github.com/kauziee-hub/hirora (`origin`, branch `main` = local `hirora-0.3.0`). Commits use the GitHub no-reply email (set in this repo's git config). Never commit personal data (real names, résumé details) — tests use fictional ones.
- Never fake provider output, latency, audio or capture results. Fixture servers live only in tests and are labelled FIXTURE. Website numbers must be measured ones.
- **One local engine only** (owner's decision, 2026-11-22): no cloud providers, API keys, access codes, provider pickers or budgets. Don't reintroduce them. Engine downloads must stay pinned (URL + size + SHA-256) and verified.
- Renderer: sandbox + contextIsolation, allowlisted IPC validated with Zod in main, CSP, no remote content.
- No audio capture before explicit consent; raw audio never persisted; history opt-in.
- Content protection (overlay left out of screen shares) is on by default since 0.2.1 at the owner's request (ADR 0008); it stays best-effort: never claim undetectability or add evasion. Website/FAQ keep the "check the interview's rules" guidance. `capture.e2e.ts` checks it against a real Edge/Chrome screen share (`HIRORA_SHARE_CHANNEL=chrome`).
- Engine servers are loopback-only (`validateLocalBaseUrl`); Hirora's Ollama uses port 11435 and never touches the user's 11434 except to unload Hirora's model from it.
- `apps/hosting/.env.local` holds Vercel CLI tokens (OIDC, Blob read-write): never commit or print it. The Vercel project still has the old `GROQ_API_KEY`/`HIRORA_ACCESS_CODE` env vars unless the owner removed them; nothing uses them.
- Never replace a published installer: each build gets a new version and its own GitHub release, so cached copies match the page's SHA-256. The GitHub token comes from the git credential manager (no `gh` CLI on this PC); never print it.
- `.npmrc` `virtual-store-dir-max-length=40` is required (NSIS fails on long pnpm paths).
- Hirora shows answers; it never clicks, types into or submits pages for the user. Answering a quiz's MCQs and coding questions and submitting them one after another was asked for on 2026-11-27 and declined: that is taking a test for someone.

## Status (2026-11-27, 0.3.7)
See `docs/PERF_RESULTS.md` (0.3.1 and 0.3.0 sections), `docs/ACCEPTANCE.md`, `CHANGELOG.md` 0.3.7 … 0.3.1, ADR 0012 and 0013, `docs/STT_STREAMING.md`. 0.3.2 = 0.3.1 + in-room capture mode, mic echo filter, `[user]`/`[other side]` transcript labels, and the opt-in live speech path (website speed figures are still the ones measured on 0.3.1). 0.3.4 = casual spoken answers (owner's feedback from a practice call: plain lists, one-line follow-ups, no pitches or stories unless asked; `VOICE_RULES` / `LENGTH_RULES` in `prompt.ts`) + an 8K answer context on the GPU tier + the reasoning fix below. 0.3.5 = 0.3.4 with a neutral follow-up rule: prompt examples must never name a real person's projects (every user's prompt carries them, and the 4B model copies them). 0.3.6 = Expand fixed (it turned thinking on and never answered; every answer now sends effort `fast`) + build walkthroughs (`isBuildWalkthrough`: ~80–120 words on parts, tools and data flow) + retrieval that finds the named project's notes (title boost for my_facts notes, room for the résumé, and on the GPU tier `wide` retrieval for walkthroughs and Expand: architecture/data-flow query words, 5 passages per note, `WIDE_EVIDENCE_PROMPT_CHARS` 10,400). 0.3.7 = no [S1] source markers or source chips (rule 4 now forbids them; the overlay strips leftovers) + answer from the screen in one key (Ctrl+Shift+O / overlay camera → `ask:screenNow` → `services.askFromScreen()`, no preview; `SCREEN_QUESTION`) + coding-round phrases in `screen.ts` (`CODING_ROUND`, `asksAboutShownProblem`: "solve this", "here's the problem", "open the link"; non-questions among them triage to `answer`) + 1600 px captures. Check with `node tools/coding-screen-check.mjs --exe …` (covers the screen for about a minute). The 4B model reads the problem reliably but its instant solutions to medium problems are often subtly wrong; thinking on fixed one but took 71 s, so answers keep thinking off.
**One assistant, no modes** (owner's decision, 0.3.1, ADR 0013): don't reintroduce mode pickers. `prompt.ts` `requestRules` covers every request type; `isAskedOfTheUser` / `isCodeTask` / `isBuildWalkthrough` add first-person, code-layout and walkthrough lines because the 4B model slipped without them. **Screen reading**: `refersToScreen` (`packages/orchestration/src/screen.ts`) + `electron/main/screenCapture.ts` (display under the cursor, 1600 px JPEG since 0.3.7, in memory only); setting `answer.screen` auto/always/off, GPU tier only. Check with `node tools/screen-check.mjs [--exe …]`: it pins a code page full-screen and topmost in Edge for about a minute, so run it when the owner isn't using the PC. Without the pin, the window active when the check started stayed in front and was captured instead.
**Live speech path** (LiveCapture + SAVA end-of-turn + LocalAgreement text, from the `gowtham` branch, merged 2026-11-23 after fixes): opt-in, `stt.streamingTranscription` false by default: accurate (first-word loss fixed with an energy-VAD start), but not faster than 0.3.1 live because Whisper decodes on the shared GPU, not the end of the turn, are the bottleneck; see `docs/STT_STREAMING.md`. Spoken trace: `node tools/stt-trace.mjs --live on|off` (prints which path ran). Silent check: `HIRORA_STT_REPLAY=1 pnpm vitest run tests/integration/stt-replay.test.ts`. SAVA model pinned in `tools/fetch-sava-onnx.mjs`, fetched by `pnpm package:win`; only onnxruntime-node's win32/x64 CPU files are packaged (`electron-builder.yml`).
Deployed: static site at https://hirora-one.vercel.app (no API: `/v1/*` and `/health` return 404 since 0.3.0); installer 0.3.7 (sha256 `b1137ca8…d178054`, 142,873,509 bytes) at https://github.com/kauziee-hub/hirora/releases/tag/v0.3.7; 0.3.6 stays at its own release. 0.3.7 is installed on this PC in `Desktop\Hirora` (real Ctrl+Shift+O checked on it with `tools/coding-screen-check.mjs`: screen read, first word 2.1 s) for the owner's interview on 2026-11-27, tested with their documents (24 realistic questions on 0.3.5, all right after fixes to the documents, median ~0.4 s; on 0.3.6 build walkthroughs take ~0.6–0.8 s to the first word and Expand 4–12 s in all; the first answer after engine start takes ~2–2.7 s). It's an NSIS install with no uninstall registry entry; update with `Hirora-Setup-<v>.exe /S /D=%USERPROFILE%\Desktop\Hirora` after closing the app. Settings backups: `settings.json.before-0.3.0` … `settings.json.before-0.3.7`, `settings.json.before-0.3.4-fix`. When the 4B model mixes up facts between projects, fix the user's documents with explicit "X is not in Y" lines, not the prompt. **Prompt budget:** evidence is capped at `EVIDENCE_PROMPT_CHARS` (7,400 chars, résumé first, résumé capped at 5,200 in `services.stableResume`) and an overflow retries once with half the evidence. With a full résumé the prompt is ~3,900–4,100 tokens, so the GPU tier runs Ollama with 8,192 tokens per slot (`answerContext` in `engine/catalog.ts` → `OLLAMA_CONTEXT_LENGTH`; at 4,096 answers were cut after 67–219 tokens); the CPU tier stays at 4,096. Never let a context-overflow 400 drop `reasoning_effort: 'none'` (`openaiCompatible.ts`): in 0.3.4 before the fix it did, and qwen3.5 then thought on every later answer and returned empty ones. Check answers on a copy of the real profile with the installed app; read `%LOCALAPPDATA%\Hirora\ollama\server.log` (`task.n_tokens`, `truncated = 1`) for prompt sizes. The owner's real profile holds interview documents (kept outside the repo, never commit them).
This PC's engine (GPU tier): whisper.cpp b5454 CUDA in `%LOCALAPPDATA%\Hirora\whisper\bin\Release` + `models\ggml-large-v3-turbo-q5_0.bin`; answers through the user's own Ollama 0.40.16 binary (`%LOCALAPPDATA%\Programs\Ollama`) run by Hirora on 127.0.0.1:11435 with `qwen3.5:4b` from `%USERPROFILE%\.ollama\models`. The user's Ollama tray app still runs on 11434. Measure on AC power: on battery the GPU throttles hard.
Tiers: GPU (NVIDIA ≥ 5.8 GB) = large-v3-turbo + `qwen3.5:4b` + early answers; CPU = Whisper small + `qwen3:1.7b` (not the hybrid `qwen3.5:2b`: no prompt-cache reuse on llama.cpp), no early answers, lean prompts, no screenshots or screen reading.
Measure with `node tools/quiet-check.mjs --exe <Hirora.exe>` (silent; a run that spoke questions aloud at night was interrupted by the owner, so prefer this one) or `node tools/interview-check.mjs --system keep` (speaks questions through the speakers).

## Design system
Light: warm canvas `#f3f2ef`, white cards (radius 22–28), ink `#1d1c35` rail and pill buttons, pastel tiles (peach/blush/lilac/mint/sky), Outfit Variable (bundled via @fontsource). Dark theme via `appearance.theme`. Overlay is always dark translucent ink glass (ADR 0006). Logo: ink squircle, white lowercase "h" whose shoulder is an arch, blush dot. Geometry lives in `src/shared/Logo.tsx`, `tools/make-icons.mjs`, the website's inline SVGs and `tools/make-og.py` (keep them in sync). Website: white page, ink pill buttons, download card modelled on the brief's search card.
