# Doing (formerly Hirora) — project conventions & status

Windows 11 x64 assistant for local file tasks, browser tasks, calls and meetings that runs **entirely on the PC** since 0.3.0. Named **Doing** since 0.4.0 (2026-11-27; it was **Hirora** from 0.2.0 and **VeyraCue** before). Since 0.5.0 workspace packages are `@doing/*`, environment overrides `DOING_*`, renderer API `window.doing`, helper `doing-audio.exe`, data `%APPDATA%\Doing` (`doing.db`) and engine `%LOCALAPPDATA%\Doing`. Compatibility aliases support old HIRORA_* launchers and window.hirora. Keep the stable Windows appId `app.hirora.desktop` so existing installations upgrade correctly. `doingMigration.ts` copies individual files and the Chromium encryption key before startup; legacy data stays available for rollback. Original specs (kept verbatim, still say VeyraCue): `docs/CLAUDE_CODE_MASTER_PROMPT.md`, `docs/VEYRACUE_IMPLEMENTATION_PLAN.md`. The repo folder was `VEYRACUE` until 2026-11-26 and is now `Hirora`; after a folder move run `CI=true pnpm install --frozen-lockfile --prefer-offline --config.confirmModulesPurge=false` (pnpm's links hold absolute paths, so builds fail with "Cannot find module …\vite.js").

## Layout
- `apps/desktop` — Electron 45 (main/preload in `electron/`, React renderer in `src/`), electron-vite 6, electron-builder 26 (`electron-builder.yml`, appId `app.hirora.desktop`).
- `apps/hosting` — Vercel project `doing` (team `omniwebora`), live at https://doing-pc.vercel.app: serves only the built website (`public/` = copy of `apps/website/dist`, gitignored). No server code since 0.3.0 (the Hirora Cloud relay was deleted). Installers are GitHub release assets of `kauziee-hub/Doing` (tag `v<version>`) since 0.3.6; 0.3.5 and older were on Vercel Blob (store `hirora-releases`), which was suspended on 2026-11-26 (billing state Inactive, 980 MB, likely the Hobby plan's Blob limits) and serves 403s.
- `apps/website` — multi-page static site (Vite MPA): `index`, `features`, `download`, `guide`, `privacy`, `faq`, `changelog` (.html), shared `partials/header.html` + `footer.html` injected by the `doing-partials` plugin in `vite.config.ts`. Positioned as a **free private assistant for PC files, browser tasks and meetings**. Model inference stays local; website submissions go to their websites. `scripts/prepare-release.mjs` copies the installer info + screenshots (`tools/site-shots.mjs`) and writes `src/release.json` (SHA-256). Hero: the Higgsfield portrait on concentric rings + soft glow (no floating chips — the owner disliked them). `tools/make-og.mjs` renders the social card in Edge.
- `native/windows-audio` — Rust WASAPI helper (`doing-audio.exe`): mic + loopback + per-process loopback, 16 kHz mono PCM16 20 ms frames, framed stdout protocol (`src/protocol.rs`, mirrored by `electron/main/audioHelper.ts`), JSON-line stdin commands.
- `apps/desktop/electron/main/engine/` — **the only engine** (ADR 0012): `catalog.ts` (pinned URLs/sizes/SHA-256 per tier), `download.ts` (resumable verified downloads, `tar.exe` unzip), `servers.ts` (whisper-server on 127.0.0.1:8178, `ollama serve` on 127.0.0.1:11435 with 2 parallel slots), `index.ts` (`EngineManager`: nvidia-smi tier, setup, start/stop, reuse of a user-installed Ollama and its models).
- `packages/contracts` (Zod schemas, IPC allowlist incl. `engine:*`, settings schema 2, secret detector) · `providers` (Ollama answer client + whisper.cpp transcriber only) · `knowledge` · `orchestration` · `settings` · `ui`.
- `electron/main/migrate.ts` — copies `%APPDATA%\VeyraCue` → `%APPDATA%\Doing` before Chromium reads `Local State` (keeps DPAPI keys decryptable); retries every launch until a marker `.migrated-from-veyracue` is written; never overwrites a Hirora profile that has its own keys (ADR 0009).
- `tests/e2e` (Playwright-for-Electron: `app.e2e.ts`, `capture.e2e.ts`, `hardware.e2e.ts`; all run with an empty engine folder; `DOING_E2E_EXE=<exe>` targets a packaged build), `tests/fixtures`.

## Rules
- Keep one project checkout at `C:\Users\KausikGH\Documents\Projects\Hirora` (owner request, 2026-11-27). Build and release from this folder; do not create a separate release worktree unless the owner explicitly asks. Published Doing 0.4.0 and the local browser assistant are consolidated here; browser integration and folder-scoped file tasks are included in 0.4.1; whole-folder moves with Undo are included in 0.5.0. A safety stash and `.git/consolidation-backup-2026-11-27` preserve the pre-consolidation work.
- Public repo: https://github.com/kauziee-hub/Doing (`origin`, branch `main` = local `main`). Commits use the GitHub no-reply email (set in this repo's git config). Never commit personal data (real names, résumé details) — tests use fictional ones.
- Never fake provider output, latency, audio or capture results. Fixture servers live only in tests and are labelled FIXTURE. Website numbers must be measured ones.
- **One local engine only** (owner's decision, 2026-11-22): no cloud providers, API keys, access codes, provider pickers or budgets. Don't reintroduce them. Engine downloads must stay pinned (URL + size + SHA-256) and verified.
- Renderer: sandbox + contextIsolation, allowlisted IPC validated with Zod in main, CSP, no remote content.
- No audio capture before explicit consent; raw audio never persisted; history opt-in.
- Content protection (overlay left out of screen shares) is on by default since 0.2.1 at the owner's request (ADR 0008); it stays best-effort: never claim undetectability or add evasion. Website/FAQ keep the "check the interview's rules" guidance. `capture.e2e.ts` checks it against a real Edge/Chrome screen share (`DOING_SHARE_CHANNEL=chrome`).
- Engine servers are loopback-only (`validateLocalBaseUrl`); Doing's Ollama uses port 11435 and never touches the user's 11434 except to unload Doing's model from it.
- `apps/hosting/.env.local` holds Vercel CLI tokens (OIDC, Blob read-write): never commit or print it. The Vercel project still has the old `GROQ_API_KEY`/`DOING_ACCESS_CODE` env vars unless the owner removed them; nothing uses them.
- Never replace a published installer: each build gets a new version and its own GitHub release, so cached copies match the page's SHA-256. The GitHub token comes from the git credential manager (no `gh` CLI on this PC); never print it.
- `.npmrc` `virtual-store-dir-max-length=40` is required (NSIS fails on long pnpm paths).
- **AI tools on this PC are MSIX-packaged** (Claude desktop `Claude_pzs8sxrjxfjjc`, Codex `OpenAI.Codex_2p2nqsd0c76g0`). Every process they start, including Doing launched from a shell or Playwright, sees `%APPDATA%`/`%LOCALAPPDATA%` through the tool's container: writes land in `%LOCALAPPDATA%\Packages\<package>\LocalCache\{Roaming,Local}`, invisible to a normal launch and to the other tool. Found 2026-11-27: the owner's real profile (`doing.db`, settings, browser trust) was in Codex's `LocalCache\Roaming\Doing`; real `%APPDATA%\Doing` didn't exist. Since 0.5.2 Doing copies the newest container profile/engine in when its own folders are empty (`containerCopy` in `doingMigration.ts`). From a tool: test with `DOING_USER_DATA`/`DOING_ENGINE_DIR`, and never conclude from a tool's view of AppData what the user's normal launch sees. Silent installs from a tool write real files to `Desktop\Doing` but their Start-menu/registry entries go to the container.
- Browser chat is explicitly requested by the owner (2026-11-27): Chrome side-panel conversation, permission-based reading, clicking, typing, multi-page submission and groups of explicitly allowed tabs (up to eight). The desktop Browser assistant page is for connection setup/status only. No task/submission checkboxes: infer a task from the chat request, and allow submission only when the current user message explicitly requests it or approves a pending action in chat. Keep access revocable and restricted to each allowed tab's site. See `docs/BROWSER_ASSISTANT.md`. Screenshot answers remain separate.
- Since local 0.3.10, browser connection is approved once in the desktop app and remembered (DPAPI credential + extension-local storage); no code entry. Persistent connection trust never restores tab/task permission. Forget browser revokes it. App quit must call `browser.shutdown()`, not `disable()` (which deliberately forgets trust).
