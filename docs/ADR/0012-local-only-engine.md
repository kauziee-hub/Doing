# ADR 0012 — One engine, on this PC, installed by the app

**Status:** accepted · 2026-11-22 (0.3.0). Supersedes ADR 0002, 0004, 0007 and 0010; amends 0009 and 0011.

**Context.** By 0.2.4 Hirora had grown a menu of paths: Hirora Cloud (our Vercel relay to Groq, behind an access code), Gemini, xAI, DeepSeek, any OpenAI-compatible endpoint, Ollama, three cloud transcribers and local Whisper, plus API-key storage, budgets and price tables. The owner measured that the fastest path is the local one (whisper.cpp + a 4B model on the GPU, 0.3–0.4 s from the end of a question to the first answer word on AC power) and asked for that to be the *only* path, set up by the app itself: install from the website, press one button, done.

**Decision.**
1. **One engine.** Live transcription is whisper.cpp's server; answers come from an Ollama runtime. Both run on `127.0.0.1` only. There are no providers, keys, access codes, budgets or cloud transcribers any more.
2. **Installed by the app, on first run.** Settings → Engine (and the onboarding "Set up" step) show the components and one *Set up Hirora* button. `electron/main/engine` downloads each file pinned to an exact URL, size and SHA-256 (GitHub release digests, Hugging Face LFS ids), resumes interrupted downloads with HTTP Range, refuses anything that doesn't match, and unpacks archives with Windows' own `tar.exe`. Answer models are pulled through Ollama's API, which verifies every layer's digest. Downloads use Electron's `net.fetch`, so the system proxy applies.
3. **Sized to the PC.** `nvidia-smi` decides the tier: an NVIDIA GPU with ≥ 5.8 GB (a "6 GB" card) gets whisper.cpp b5454 CUDA 12.4 + `ggml-large-v3-turbo-q5_0` + `qwen3.5:4b` (6.2 GB to download); every other PC gets the CPU build + `ggml-small-q5_1` + `qwen3:1.7b` (3.2 GB). Not `qwen3.5:2b`: Qwen 3.5 is a hybrid (recurrent) model, and llama.cpp re-reads the whole prompt for every question with it (4.1–4.5 s to the first token on a CPU), while `qwen3:1.7b` reuses the cached instructions (0.16–0.18 s after the first question). It reads no images, so screenshots need the GPU tier. Users can force either tier in Settings.
4. **Hirora's own Ollama server.** The app runs `ollama serve` on port 11435 (never the user's 11434) with two parallel slots, so the short "is this a question for me?" check runs while an answer is being written (it used to go to the cloud, ADR 0011 point 4). It reuses an Ollama the user already installed (binary and model folder), so nothing is downloaded twice; otherwise it downloads the official 0.40.16 Windows zip and keeps the runtime and models under `%LOCALAPPDATA%\Hirora`, so deleting that folder removes everything Hirora downloaded. If the user's own Ollama holds our model in GPU memory, Hirora asks it to unload that model before loading its own copy.
5. **Hirora Cloud is gone.** The relay functions were deleted; the Vercel project (`apps/hosting`) only serves the website.
6. **Upgrades.** Settings schema 2 drops the old `providers`, `budget`, `stt.provider` and embedding fields when a 0.2.x file is loaded; everything else (audio devices, overlay, answer style, documents, history) is kept. The old encrypted `secrets.json` is not read; *Delete all data* removes it.

**Consequences.** Nothing a user says leaves the PC, there is no server to pay for or to rate-limit friends, and Hirora works offline after setup. The price is a one-time 3.2–6.2 GB download and hardware-dependent speed: a laptop must be on AC power for GPU speed, and PCs without an NVIDIA GPU answer more slowly (see `docs/PERF_RESULTS.md`). Answer quality is that of a 1.7B/4B model. AMD/Intel GPUs use the CPU tier for now.
